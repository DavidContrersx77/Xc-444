MÓDULO 01 · COLABORACIÓN

Control de versiones

El historial inteligente de un proyecto: registra qué cambió, quién lo hizo y cómo recuperar estados anteriores.

⌘01

¿Qué es el control de versiones?

Es un sistema que registra modificaciones realizadas en archivos a lo largo del tiempo. Permite consultar versiones anteriores, comparar diferencias, recuperar contenido y coordinar el trabajo de varias personas. Aunque se utiliza mucho en programación, también puede administrar documentos y otros archivos.

Un repositorio es el espacio donde se conserva el proyecto y su historial. Cada registro de cambio suele incluir una descripción, autor, fecha y referencia a la versión anterior.

Tipos de sistemas de control de versiones

LOCAL▣

Control local

Guarda revisiones en el propio equipo, normalmente mediante copias o una base de datos local.

  • Características: funciona sin servidor y registra cambios en un solo entorno.
  • Ventajas: sencillo, rápido y útil para proyectos individuales.
  • Desventajas: colaboración limitada y riesgo si el equipo se daña.

Ejemplo: mantener copias numeradas de un archivo o usar una herramienta local de historial.

CENTRALIZADO▤

Control centralizado (CVCS)

Existe un servidor central que conserva el repositorio; los clientes obtienen archivos y envían sus cambios a ese punto.

  • Características: servidor único, permisos centralizados y versiones compartidas.
  • Ventajas: administración sencilla y visibilidad del trabajo del equipo.
  • Desventajas: dependencia de la conexión y punto único de falla si el servidor deja de estar disponible.

Ejemplos: Apache Subversion (SVN), CVS y Perforce.

DISTRIBUIDO◈

Control distribuido (DVCS)

Cada desarrollador dispone de una copia completa del repositorio y de su historial. Puede registrar cambios localmente y sincronizarlos después.

  • Características: repositorios completos, ramas y trabajo sin conexión.
  • Ventajas: flexibilidad, copias redundantes y colaboración mediante ramas.
  • Desventajas: requiere aprender flujos de sincronización y resolver conflictos de integración.

Ejemplos: Git y Mercurial.

✦
Importante: Git no es lo mismo que GitHub.

Git es el sistema distribuido que registra versiones. GitHub es una plataforma que aloja repositorios Git y añade colaboración, revisión de código, incidencias y automatizaciones.

¿Cómo funciona Git?

El flujo habitual consiste en modificar archivos, seleccionar los cambios que se incluirán, crear un commit y, cuando se trabaja con un repositorio remoto, sincronizar el historial.

MÓDULO 02 · INFORMACIÓN

Persistencia y acceso a datos

Los datos deben permanecer disponibles después de cerrar una aplicación, reiniciar el dispositivo o cambiar de pantalla.

▤02

Definición

La persistencia de datos es la capacidad de conservar información durante un periodo que supera la ejecución inmediata de un programa. En móviles permite guardar preferencias, cuentas, registros, archivos, contenido descargado y datos que deben sincronizarse entre dispositivos.

Características principales

  • Durabilidad: los datos sobreviven al cierre de la app según el medio utilizado.
  • Disponibilidad: la información puede consultarse cuando se necesita.
  • Integridad: se busca evitar registros incompletos o inconsistentes.
  • Seguridad: se controla quién puede leer o modificar la información.
  • Rendimiento: se elige el medio adecuado según tamaño y frecuencia de acceso.
  • Sincronización: los datos locales y remotos pueden mantenerse coordinados.

Formas de persistencia en dispositivos móviles

▧

1. Archivos

La aplicación guarda documentos dentro del almacenamiento interno o en ubicaciones compartidas. Es apropiado para imágenes, audio, video, PDF, archivos JSON, exportaciones y caché.

Ventajas: estructura flexible y fácil intercambio de archivos. Limitaciones: buscar y actualizar datos relacionados puede ser menos eficiente que en una base de datos.

Ejemplo: guardar una foto de perfil o descargar un PDF.

▤

2. Bases de datos locales

Conservan datos estructurados dentro del dispositivo. SQLite es un motor relacional ligero; Room es una capa de persistencia de Android Jetpack que facilita trabajar con SQLite mediante entidades, DAO y consultas verificables.

Ventajas: consultas, relaciones, transacciones y funcionamiento sin conexión. Limitaciones: la información queda en el dispositivo y requiere una estrategia para sincronizarse con otros equipos.

Ejemplo: guardar productos, notas, pedidos o historial de actividad.

☁

3. Bases remotas y servicios web

Los datos se almacenan en servidores y se consultan mediante una API o un SDK. La aplicación envía solicitudes HTTP, recibe respuestas —frecuentemente JSON— y presenta los resultados.

Ventajas: acceso desde varios dispositivos, respaldo central y colaboración. Limitaciones: depende de red, servidor, costos y controles de seguridad.

Ejemplo: consultar el catálogo de una tienda desde una API REST.

Mecanismos de acceso y control

Bibliotecas de clases

Conjuntos de clases y métodos que encapsulan operaciones de lectura, escritura, permisos y manejo de archivos. En Android pueden utilizarse APIs del sistema y bibliotecas como DataStore.

Clases de SQLite y Room

SQLite permite ejecutar sentencias SQL. Room organiza el acceso mediante @Entity (tabla), @Dao (operaciones) y @Database (configuración de la base de datos). Las consultas se ejecutan fuera del hilo principal.

Mapeo objeto-relacional (ORM)

Relaciona objetos del lenguaje de programación con tablas de una base de datos. El desarrollador trabaja con objetos y el ORM traduce operaciones a consultas. Room aplica este enfoque en Android; en otros ecosistemas existen Entity Framework y Hibernate.

Autenticación y consumo de servicios web

01 · Identificar

El usuario introduce credenciales o utiliza un proveedor de identidad.

02 · Verificar

El servidor comprueba la identidad y puede emitir un token de acceso.

03 · Solicitar

La app realiza una petición HTTPS a la API y envía el token en el encabezado correspondiente.

04 · Autorizar

El servidor valida permisos y responde con datos o un error controlado.

05 · Actualizar

La app procesa la respuesta, actualiza la interfaz y, si procede, sincroniza datos locales.

⚠
Buenas prácticas

No guardes contraseñas en texto plano ni incluyas claves privadas dentro de la app. Usa HTTPS, tokens de vida limitada, almacenamiento seguro para credenciales y validación de permisos en el servidor.

IDEA DE CONSULTA A UNA API · JAVASCRIPT
fetch('https://api.ejemplo.com/productos', {
  headers: { Authorization: `Bearer ${token}` }
})
  .then(respuesta => {
    if (!respuesta.ok) throw new Error('Error de red');
    return respuesta.json();
  })
  .then(datos => console.log(datos))
  .catch(error => console.error(error));

Ejemplo didáctico: la URL y el token son ilustrativos. En una aplicación real se debe gestionar la expiración del token, los errores, los tiempos de espera y la política de reintentos.

MÓDULO 03 · HARDWARE

Gestión de sensores

Los sensores permiten que una aplicación detecte movimiento, orientación y condiciones del entorno físico.

◉03

¿Qué son los sensores?

Son componentes físicos o mecanismos de software que detectan magnitudes del entorno o del propio dispositivo y las convierten en datos que una aplicación puede interpretar. En Android se accede a muchos de ellos mediante el framework de sensores y sus clases de administración y escucha de eventos.

Algunos sensores son de hardware, porque existen como componentes físicos; otros son virtuales, porque calculan sus valores combinando información de varios sensores.

Tipos de sensores en dispositivos móviles

↗

Acelerómetro

Mide aceleración en los ejes X, Y y Z, incluida la gravedad. Se usa para detectar inclinación, movimiento y sacudidas.

⟳

Giroscopio

Mide la velocidad angular o rotación. Es útil en juegos, realidad aumentada y estabilización.

⌖

Proximidad

Detecta si un objeto está cerca de la pantalla, por ejemplo al acercar el teléfono al oído.

☼

Luz ambiental

Mide la iluminación del entorno y puede ayudar a ajustar el brillo de la pantalla.

◈

Magnetómetro

Detecta el campo magnético terrestre y contribuye a determinar la dirección de una brújula.

⌖

GPS / ubicación

Obtiene la posición geográfica mediante proveedores de ubicación; requiere permisos y consideración de privacidad.

⌁

Barómetro

Mide presión atmosférica. Puede ayudar a estimar cambios de altitud.

♡

Ritmo cardiaco

En dispositivos compatibles, mide señales relacionadas con el pulso. Su disponibilidad depende del hardware y permisos.

Proceso de gestión de sensores

1. Habilitación

Comprobar disponibilidad del sensor, explicar su uso y solicitar permisos cuando corresponda.

2. Obtención

Registrar un listener o solicitar actualizaciones al servicio correspondiente para recibir lecturas.

3. Procesamiento

Filtrar ruido, interpretar unidades, combinar valores y convertir lecturas en eventos útiles.

4. Finalización

Detener las actualizaciones cuando ya no se necesitan para ahorrar batería y proteger la privacidad.

Ejemplo: una aplicación de actividad física consulta el acelerómetro para estimar movimiento. Filtra lecturas, identifica patrones compatibles con pasos y presenta un conteo aproximado. No debe asumir que cada variación equivale a un paso.
◉
Consumo y privacidad

Las lecturas frecuentes consumen energía. Solicita únicamente los permisos necesarios, explica para qué se usa cada dato y evita recopilar información sensible sin justificación.

MÓDULO 04 · EXPERIENCIA VISUAL

Uso de recursos multimedia

Imágenes, sonidos, videos y animaciones convierten los datos y las acciones en experiencias claras y atractivas.

▧04

Definición e importancia

Los recursos multimedia son elementos digitales que combinan información visual, sonora o animada dentro de una aplicación. Se utilizan para comunicar, orientar, entretener, representar datos y facilitar la interacción. Deben optimizarse para el tamaño de pantalla, el rendimiento, la accesibilidad y el consumo de red.

VISUAL

Imágenes

Fotografías, iconos, ilustraciones, logotipos y gráficos. Formatos frecuentes: JPEG, PNG, WebP, SVG y AVIF, según compatibilidad y uso.

SONIDO

Audio

Música, efectos, voz y narraciones. Formatos comunes: MP3, AAC, WAV y OGG. Conviene controlar volumen, enfoque de audio y permisos del micrófono.

MOVIMIENTO

Video

Clips de demostración, tutoriales y transmisiones. MP4 con H.264 es una combinación ampliamente compatible; la resolución y compresión afectan tamaño y batería.

DINÁMICO

Animaciones

Transiciones, indicadores, microinteracciones y gráficos animados. Pueden usar recursos vectoriales, animaciones declarativas o secuencias de imágenes.

¿Dónde se almacenan en un proyecto Android?

Los recursos se organizan en carpetas dentro del módulo de la aplicación, habitualmente bajo app/src/main/res/. La estructura ayuda al sistema a seleccionar recursos según densidad, idioma o configuración.

📁 app / src / main /
📁 res Recursos compilados de la app
📁 drawable/ Imágenes y gráficos
📁 mipmap/ Iconos de lanzador
📁 raw/ Audio, video y archivos sin procesar
📁 anim/ y animator/ Definiciones de animación
📁 values/ Colores, cadenas y estilos
📁 assets Archivos que se leen como contenido original

Componentes de software multimedia

Reproducción

Media3 / ExoPlayer permite reproducir contenido de audio y video. Los controles de reproducción administran pausa, avance, volumen y estado.

Captura

CameraX simplifica el uso de la cámara. APIs de audio permiten grabar y procesar sonido, siempre con permisos y avisos adecuados.

Presentación

Image loading libraries, componentes de interfaz y APIs gráficas cargan, escalan y muestran medios de forma eficiente.

✧
Optimización y accesibilidad

Comprime imágenes, usa miniaturas, adapta resoluciones, carga contenido bajo demanda, añade texto alternativo o descripciones y ofrece subtítulos cuando el contenido audiovisual lo requiera.

MÓDULO 05 · PROCESOS Y COMUNICACIÓN

Servicios y notificaciones

Las aplicaciones pueden realizar operaciones fuera de la pantalla activa y avisar al usuario cuando existe información relevante.

⌁05

Definición

Un servicio es un componente de aplicación que puede realizar operaciones sin proporcionar una interfaz propia. Las notificaciones son mensajes del sistema que informan al usuario sobre eventos, recordatorios, mensajes o el estado de una tarea.

¿Qué son las tareas en segundo plano?

Son operaciones que se ejecutan cuando la persona no está interactuando directamente con la pantalla relacionada. Por ejemplo, sincronizar información, subir una fotografía, descargar contenido o procesar datos. Android limita el trabajo en segundo plano para cuidar batería, memoria y privacidad.

EJEMPLO VISUAL DE UNA NOTIFICACIÓN

Tipos de ejecución

TRABAJO PROGRAMADO

WorkManager

Recomendado para tareas que deben ejecutarse de forma confiable aunque el usuario salga de la app o el dispositivo se reinicie. Permite establecer condiciones como conectividad y batería.

Ejemplo: sincronizar pedidos pendientes cuando haya conexión.

SERVICIO EN PRIMER PLANO

Foreground service

Para operaciones perceptibles que deben continuar activamente, como navegación o reproducción de audio. Debe mostrar una notificación y cumplir los tipos y permisos requeridos por la versión de Android.

Ejemplo: registrar una ruta durante una sesión de ejercicio.

TAREA ASÍNCRONA

Corrutinas / hilos

Permiten ejecutar operaciones fuera del hilo principal para no congelar la interfaz. Son apropiados para trabajo ligado al proceso y que puede cancelarse si la app deja de estar activa.

Ejemplo: consultar una API y actualizar una lista.

Proceso de implementación

Proveedor de contenido

Define una fuente de datos estructurada y una interfaz de acceso mediante URI. En Android, ContentProvider permite compartir datos con otras aplicaciones aplicando permisos.

Tarea en segundo plano

Identifica si el trabajo debe ser inmediato o programado; elige WorkManager, una operación asíncrona o un servicio en primer plano según duración y visibilidad.

Notificación

Crea un canal en Android, solicita autorización de notificaciones cuando la versión lo requiera, construye el contenido y define la acción al tocarla.

Pruebas y control

Comprueba permisos, restricciones del sistema, consumo de batería, errores de red y comportamiento cuando la app se cierra.

Servicios de cómputo en la nube

La nube ofrece infraestructura y servicios remotos que una app móvil puede consumir mediante internet. Permite autenticar usuarios, almacenar archivos, guardar datos, enviar notificaciones y ejecutar lógica del lado del servidor.

MÓDULO 06 · HERRAMIENTAS

Librerías y toolkits

Reutiliza soluciones existentes para construir aplicaciones con menos código repetitivo y mejores prácticas.

⬡06

¿Qué es una librería?

Una librería es un conjunto reutilizable de funciones, clases y componentes que resuelven tareas específicas. El programa llama a la librería cuando necesita una capacidad: por ejemplo, consultar una base de datos, cargar imágenes o realizar peticiones HTTP.

¿Qué es un toolkit?

Un toolkit o conjunto de herramientas reúne componentes y utilidades para desarrollar una parte amplia de una aplicación o incluso su interfaz completa. Puede incluir widgets, sistema de diseño, herramientas de compilación, depuración y acceso a capacidades del dispositivo.

◇
Diferencia clave

Una librería suele resolver una función o problema concreto; un toolkit ofrece un conjunto más amplio y coordinado de herramientas para construir una solución. En la práctica, algunos frameworks incluyen librerías y toolkits, por lo que las categorías pueden solaparse.

MÓDULO 07 · CALIDAD Y PROTECCIÓN

Depuración y seguridad

Una aplicación confiable se prueba, se observa y se protege desde las primeras etapas del desarrollo.

⛨07

¿Qué es la depuración?

La depuración (debugging) es el proceso de localizar, analizar y corregir errores de un programa. Un error puede provocar cierres inesperados, resultados incorrectos, lentitud, consumo excesivo de memoria o fallos de comunicación.

¿Qué es la seguridad?

Es el conjunto de medidas técnicas y organizativas que protegen la aplicación, sus usuarios, dispositivos y datos frente a accesos no autorizados, manipulación, pérdida o exposición.

Herramientas de depuración en el entorno móvil

⌕

Debugger de Android Studio

Permite pausar la ejecución con breakpoints, avanzar línea por línea, inspeccionar variables y analizar la pila de llamadas.

▤

Logcat

Muestra registros del sistema y de la aplicación. Ayuda a identificar excepciones, mensajes y errores durante la ejecución.

◫

Profiler

Permite observar uso de CPU, memoria y red para detectar cuellos de botella y consumo excesivo de recursos.

✓

Pruebas automatizadas

JUnit, pruebas instrumentadas y Espresso ayudan a verificar lógica, componentes e interacción de la interfaz.

⌁

Lint e inspecciones

Detectan problemas potenciales, patrones inseguros, accesibilidad y oportunidades de mejora antes de publicar.

⌘

ADB

Android Debug Bridge permite comunicarse con emuladores y dispositivos para instalar, ejecutar y diagnosticar aplicaciones.

Principios y prácticas de seguridad

01

Autenticación y autorización

Verifica la identidad y comprueba permisos para cada recurso. No confíes únicamente en controles de la interfaz.

02

Protección de datos

Usa HTTPS, cifrado cuando corresponda y almacenamiento seguro para información sensible. Evita registrar contraseñas o tokens en logs.

03

Permisos mínimos

Solicita solo los permisos necesarios, en el momento oportuno y explicando su finalidad.

04

Validación de entradas

Valida datos en el cliente y en el servidor. Usa consultas parametrizadas para reducir riesgos de inyección.

05

Dependencias actualizadas

Revisa bibliotecas, corrige vulnerabilidades conocidas y elimina componentes que ya no se utilizan.

06

Pruebas y revisión

Prueba escenarios de error, revisa configuraciones de producción y analiza el comportamiento antes de publicar.

⛨
Seguridad desde el diseño

La seguridad no es una función que se agrega al final. Debe considerarse al diseñar almacenamiento, autenticación, permisos, comunicación de red, registros y actualizaciones.
